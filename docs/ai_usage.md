# AI 工具使用声明（诚实边界）

## 用了什么

本项目开发全程使用 AI 编程助手（WorkBuddy / Claude Code 类工具）辅助：
- 脚手架代码（loader / splitter / graph / eval 脚本的初版结构）；
- 文档与笔记的草稿（后经人工核对修改）；
- 报错信息的快速定位建议。

## AI 的边界在哪

以下工作 AI **没有**、也无法代替完成，全部由人主导：

1. **语料源决策**：AI 最初按旧文档地址抓取，抓到 30 篇"成功"但内容只有 2 种重复。
   是人发现 md5 去重异常，查明旧站已 301 迁移，改从 sitemap 取真实 URL 并加了内容级去重校验。
2. **评估集的人工校验**：60 条 golden_qa 中 16 条综合题与全部 8 条越界题为人工书写；
   自动生成的 60 条候选中有 16 条因"指代不明/答案不在原文"被程序化预筛剔除。
3. **失败归因**：评估报告里的每条失败 case 归因（术语差异 / 主题竞争 / 切分打散）
   由人工逐条填写。
4. **实验设计与结论**：对比实验"一次一变量"的变量选择、假设、以及结论
   （接受/拒绝假设）由人完成，AI 只负责执行。
5. **三次平台切换的排错**（官方 → CloseAI 中转 → 千问AI平台）：
   base_url 路径、模型名可用性都是人通过 curl 实测确认，AI 建议的默认值两次都不对。

## 推翻了 AI 的哪些建议

- AI 建议"用 similarity score 阈值做拒答"——实测越界组与正常组 top1 分数只差 0.11，
  阈值不可分，改走 grade 节点语义判断（CRAG）；
- AI 生成的大代码块切分策略会把函数切碎——人工改为"代码块整体不可切分"；
- AI 写的 `str.format` 注入含 JSON 示例的 prompt 模板——线上直接 KeyError，改为 replace。

## 结论

AI 工具在本项目中的角色是**加速器**（把"写"变快），不是**决策者**
（"做什么、为什么、对不对"由人判断）。2026 年了，这比假装全手写更可信。
