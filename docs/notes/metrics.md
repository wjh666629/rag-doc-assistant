# Hit@5 与 MRR：为什么两个都要看

**Hit@k** 回答的是"找没找到"：标准答案来源只要出现在前 k 条里就记 1，不管排第几，全体取平均。它是**召回覆盖**的度量——系统有没有能力把正确文档捞进候选集。

**MRR** 回答的是"排得前不前"：取第一个正确来源的排名 r，记 1/r（没命中记 0），全体取平均。正确来源排第 1 得 1.0，第 2 得 0.5，第 5 得 0.2。它是**排序质量**的度量。

两者互补：两个系统的 Hit@5 可能都是 0.8，但一个把正确文档稳定排在第 1（MRR≈0.8），另一个总排在第 4、5 位（MRR≈0.25）。对用户而言后者体验差得多——因为真正进 prompt 的往往只有前 2~3 条，排第 5 的文档约等于没检索到。

实战含义：**Hit@5 掉了先查召回链路（切分、embedding、top_k），MRR 掉了先查排序链路（是否该加 rerank）**。本仓库基线 Hit@5=0.5769、MRR=0.4427，说明"能捞到但排不准"，因此 Day 7 的实验选了 rerank 而非继续调 top_k。
