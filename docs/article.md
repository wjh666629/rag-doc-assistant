# 7 天从 0 搭一个能评估的 RAG+Agent 系统：我踩过的 17 个坑

> 说明：这是我的 7 天求职作品复盘。全部代码与报告见 GitHub 仓库（README 附完整评估数字与已知缺陷）。

## 为什么做这个项目

目标岗位的 JD 里写着：RAG、LangChain/LangGraph、Agent、Prompt、评估、数据敏感。我没有挑一个"看起来高级"的题目，而是反推：面试官要看到什么？答案是四件事——**会搭、会调、会测、会写**。所以项目不是"一个能跑的 demo"，而是"一套自带评估流水线的 CRAG 系统"：60 篇 LangChain/LangGraph 官方文档语料、60 条人工校验评估集、Hit@5/MRR + Ragas 三指标 + 一键对比报告，外加两组消融实验。

## 架构一张图

```
问题 → router（需要检索吗？）
       ├─ 闲聊 → generate（直答）
       └─ 需要 → retrieve（Chroma top_k）
              → grade（LLM 判相关性）
                 ├─ relevant → generate（带 [1][2] 引用）
                 └─ irrelevant → rewrite（重写查询）→ retrieve（最多 1 次）
                                → 仍不相关 → 诚实拒答
```

选 CRAG 而不是多 Agent，因为 7 天里它是"复杂度刚好能展示图的价值、又不至于做不完"的甜区。

## 三个最深的坑（完整 17 条见仓库 docs/pitfalls.md）

### 坑 1：抓到了 30 篇"成功"的重复文档

Day 1 抓 LangChain 官方文档，30 篇全部"抓取成功"。抽查时发现多数字符数完全一样——旧域名已整站 301，30 个 URL 抓到的其实是同一个页面（md5 去重后只剩 2 种）。教训是**"请求成功"不等于"拿到了你要的东西"**。后来我从 sitemap.xml 取真实 URL，并在抓取脚本里加了正文哈希去重：内容重复的页面直接记失败。第二条线是发现 Mintlify 站点支持 URL 加 `.md` 后缀直接返回原生 markdown，代码块完整度从"经常丢失"变成 100%。

### 坑 2：指标差的原因不是你以为的那个

自检时「LangGraph 中如何定义 state？」全部拒答。第一反应是"中文问题检索英文语料不行"，做了中英对照实验后发现**中英文命中率一样差**——真正原因是语料是新版 agent 文档，压根没有 LCEL/state 的内容。扩抓 30 篇 LangGraph 文档重建索引后，top1 立刻命中正确的 `use-graph-api.md`。这条经验后来写进了评估方法论：检索指标差，先做"中英对照 + 看 top1 实际内容"二分定位，再决定改 embedding 还是改语料。

### 坑 3：`--limit 20` 让拒答率变成 0.0

跑评估时图省事加了 `--limit 20`，报告出来 `refusal_rate: 0.0`，看起来像"系统从不拒答"。排查发现：越界题是人工书写的，排在评估集文件末尾，`items[:20]` 把它们全切了——**抽样方式改变了难度结构，指标变得没有意义**。修成分层抽样（越界题必留）后，拒答率恢复真实值。这条坑让我对"评估集的任何处理都必须保持难度结构"这句话有了肌肉记忆。

第 16、17 条坑都来自 Day 7 的对比实验，可能是最值钱的两条：**强化生成 prompt 救不了拒答率，因为 8 条越界题里 5 条在 router 节点就被判"无需检索"、走了直接回答分支，改动根本作用不到失效路径上**；以及 LLM 裁判（Ragas）在检索结果完全相同的情况下指标仍波动 ±0.08——单次运行的 LLM-as-judge 数字不可比较，prompt 类消融必须多次取均值。

## 我怎么衡量"好不好"

系统的每一项指标都来自可复现的命令，不是体感：

| 指标 | 数值 | 说明 |
|---|---|---|
| Hit@5 | 0.577 | 自研指标（未调现成库），60 条人工校验评估集 |
| MRR | 0.44 | 排序质量是短板 → Day 7 实验靶子 |
| Faithfulness | 0.851 | Ragas，judge temperature=0 |
| 越界拒答正确率 | 0.500 | 8 条人工书写越界题；Day 7 定位出瓶颈在 router 节点 |
| 对比实验 | E1（chunk 300）/ E3（prompt v2）均不采纳 | 每组独立 config，一次一变量；失败后逐题归因 |

## 不足与下一步

1. 多跳问题（需串联 3+ 文档）召回率低——下一步做 query decomposition；
2. 评估集 60 条偏小，指标波动约 ±0.05，结论只看趋势；
3. 表格类内容切分后语义断裂，未做特殊处理。

## 诚实声明

本项目使用 AI 编程助手辅助开发（脚手架、文档草稿），但语料决策、评估集人工校验、失败归因、实验设计与三次平台切换排错均由人完成，详见仓库 `docs/ai_usage.md`。
